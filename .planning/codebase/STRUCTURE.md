## Key File Locations

**Entry Points:**
- `catalog_manager_extended.py`: Main REST API server - responds to TMF endpoints on port 8080, database persistence
- `catalog_manager.py`: Simplified in-memory REST API - no database, good for testing MCP server separately
- `mcp_fastmcp_server_extended.py`: Main MCP server - 18 tools (TMF + catalog) + 8 resources on port 8090
- `mcp_fastmcp_server.py`: Simpler MCP server - core tools only, easier to understand

**Configuration:**
- `.env`: Environment variables (DB_HOST, DB_PORT, DB_NAME, DB_USER, DB_PASSWORD, PORT, CATALOG_MANAGER_URL)
- `config.yaml`: Configuration (unused - env vars are authoritative)
- `docker-compose.yml`: Container orchestration with postgres, catalog-manager, mcp-server services
- `Dockerfile.catalog.enhanced`: Builds catalog-manager image (runs catalog_manager_extended.py)
- `Dockerfile.mcp.enhanced`: Builds mcp-server image (runs mcp_fastmcp_server_extended.py)

**Database Schema:**
- `init_db_extended.sql`: Production schema - creates service_specifications, customers, orders, service_coverage, service_activations, plus product_service_links, customer_addresses, address_history (extended)
- `init_db.sql`: Minimal schema - essential tables only, lighter seed data
- Both are idempotent (CREATE TABLE IF NOT EXISTS)

**Core Logic:**
- `catalog_manager_extended.py`: TMF API implementation
  - `/tmf637/serviceQualification`: Service availability check
  - `/tmf629/customer/<id>`: Customer info lookup (GET), create (POST), update (PATCH), delete (DELETE)
  - `/tmf622/productOrder`: Order creation (POST), listing (GET), status update, cancel, delete
  - `/tmf640/serviceActivation`: Service activation endpoint
  - `/api/service-specifications`: Create/list service specs
  - `/api/product-offerings`: Create/list product offerings
  - `/api/geographic-locations`: List locations with coverage
- `mcp_fastmcp_server_extended.py`: MCP wrapper layer
  - Tools: service_qualification, customer_management, product_ordering, order_management, cancel_order, delete_order, update_order_status, service_activation, list_service_specifications, list_product_offerings, list_geographic_locations, sync_catalog_data, create_service_specification, create_product_offering, link_offering_to_specification, add_geographic_coverage (16 TMF/catalog tools)
  - Resources: customers://list, services://catalog, products://catalog, coverage://map, customer://{id}, orders://recent, orders://customer/{id}, catalog://integrity (8 read-only browsable resources)

**Utilities:**
- `demo_reset.py`: Tool to clear all orders and reset state (useful for demo reruns)
- `catalog_diagnostics.py`: Health check and schema validation utility
- `mcp_bridge.py`: Simple HTTP bridge between catalog manager and external clients (deprecated)

**SQL Utilities:**
- `create_product_service_links.sql`: Create product-service relationships
- `add_business_to_server1.sql`: Add business/account data
- `fix_server2_critical.sql`: Fix critical data issues (historical)
- `optional_deprecate_unused_specs.sql`: Mark unused service specs as inactive

**Testing & Validation:**
- `requirements_test.txt`: Test dependencies (minimal)
- `test_*.py` files: Ad-hoc test scripts (test_enhanced.py, test_complete_fixes.py, quick_test.py, test_data_format_fix.py)
- No formal test suite (pytest not configured, no tests/ directory)

## Naming Conventions

**Files:**
- Python files: snake_case (catalog_manager_extended.py, mcp_fastmcp_server_extended.py)
- SQL files: snake_case (init_db.sql, init_db_extended.sql)
- Dockerfiles: Dockerfile.{component}.{variant} (Dockerfile.catalog.enhanced, Dockerfile.mcp.enhanced)
- Requirements: requirements_{component}.txt (requirements_catalog.txt, requirements_mcp.txt)
- Backups: {filename}_backup.py or {filename}.backup.{timestamp} (catalog_manager_extended_backup_20250730_155411.py)

**Directories:**
- lowercase with hyphens for logical grouping (enhanced/, enhanced-deployment/, logs/catalog/, logs/mcp/)
- dot-prefixed for hidden/system dirs (.git/, .planning/, .env)

**Python Modules:**
- Classes: Not heavily used; mostly procedural with Flask route handlers and MCP tool functions
- Functions: snake_case (get_db_connection, log_audit, ensure_session)
- Variables: snake_case (customer_id, service_type, async session = aiohttp.ClientSession())
- Flask route functions: snake_case matching endpoint purpose (service_qualification, customer_management)
- MCP tool functions: snake_case matching TMF action (service_qualification, product_ordering, order_management)

**Environment Variables:**
- UPPERCASE with underscores (DB_HOST, DB_PORT, DB_NAME, DB_USER, DB_PASSWORD, CATALOG_MANAGER_URL, PORT, HOST)
- Sourced from .env file or container environment at runtime

**Database:**
- Tables: snake_case (service_specifications, service_coverage, order_addresses)
- Columns: snake_case (customer_id, service_type, has_overdue_payments)
- Indexes: idx_{table}_{column(s)} (idx_customers_status, idx_orders_customer, idx_coverage_location)

## Where to Add New Code

**New TMF Forum API Endpoint:**
- REST endpoint in `catalog_manager_extended.py`: Add @app.route('/tmf{spec_number}/endpoint', methods=['POST/GET/PATCH/DELETE']), implement handler with get_db_connection(), cursor.execute(), jsonify(result)
- MCP tool wrapper in `mcp_fastmcp_server_extended.py`: Add @mcp.tool() async def, call REST endpoint via session.post/get, log_audit(), raise Exception on error
- Database schema in `init_db_extended.sql`: Add CREATE TABLE IF NOT EXISTS for new data, INSERT demo data
- Example: To add TMF650 (Product Catalog): create_product_catalog route in catalog_manager_extended.py, add product_catalog MCP tool, create products table in init_db_extended.sql

**New Catalog Feature (non-TMF):**
- REST endpoint in `catalog_manager_extended.py` under /api/ path: @app.route('/api/feature-name', methods=[...])
- MCP tool in `mcp_fastmcp_server_extended.py`: @mcp.tool() async def feature_name(...)
- MCP resource for read-only browsing: @mcp.resource("feature://list") async def list_features() -> str
- Database: Extend existing tables or add new tables in init_db_extended.sql

**Database Migration:**
- Add new schema changes to `init_db_extended.sql` (idempotent: CREATE TABLE IF NOT EXISTS, ALTER TABLE ADD COLUMN IF NOT EXISTS)
- Update docker-compose.yml volumes to mount init_db_extended.sql (already done)
- To apply to running container: docker exec telecom_postgres psql -U telecom_user -d telecom_catalog -f migration.sql
- To reset: docker-compose down -v && docker-compose up -d (nukes postgres_data volume)

**Testing New Feature:**
- Add test function to `test_enhanced.py` or create new `test_feature.py`
- Use requests library to call REST endpoints directly: requests.post('http://localhost:8080/api/feature')
- Or use MCP tool directly in Python script: await mcp.tool_name(args)
- No pytest.ini or test runner configured; use python test_file.py to execute

**Utility Script (non-running):**
- Add to root level (e.g., migrate_data.py, validate_schema.py)
- Naming: verb_noun_action.py (e.g., add_business_to_server1.sql, fix_server2_critical.sql)
- Document purpose in docstring and STRUCTURE.md

## Database Schema Overview

**service_specifications:**
- Columns: id (PK), name, service_type, description, created_at
- Purpose: Catalog of available service types (fiber_internet, cable_internet, mobile, tv, etc.)
- Seeded: Yes, ~12 specs in init_db_extended.sql

**customers:**
- Columns: id (PK), name, account_status, credit_score, has_overdue_payments, address fields, created_at
- Purpose: Customer master data
- Seeded: Yes, 6 demo customers (IDs 8452934-8452939)

**service_coverage:**
- Columns: id (auto), street_name, city, service_type, max_speed_mbps, available, created_at
- Purpose: Geographic service availability matrix
- Seeded: Yes, coverage for Main Street, Oak Avenue, Elm Street, etc. with Springfield/Shelbyville cities

**orders:**
- Columns: id (PK), order_date, external_id, customer_id (FK), product_offering_id, status, created_at
- Purpose: Product orders (TMF622 entities)
- Seeded: No (populated at runtime)

**service_activations:**
- Columns: id (PK), service_name, service_type, service_specification_id, status, created_at
- Purpose: Service activation records (TMF640 entities)
- Seeded: No (populated at runtime)

**Additional tables (init_db_extended.sql only):**
- order_addresses: Delivery address per order
- activation_addresses: Service address per activation
- product_service_links: Link between product offerings and service specifications (extended schema)
- customer_addresses: Additional addresses per customer (extended schema)
- address_history: Audit trail of address changes (extended schema)
